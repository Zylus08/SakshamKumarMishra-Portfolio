### 2. Project AXIOM Source Audit

#### 2.1 Scope & Positioning
- **Dialect & Subsystem Scope:** Read-only analytical SQL query engine. Not an ACID transactional DBMS or storage engine replacement.
- **Frontend Architecture:** Custom lexer tracking source coordinates; recursive-descent statement parser and Pratt-style expression parser; AST generation with semantic binder resolving identifiers against CSV table schemas.
- **Query Optimization:** Rule-based query optimizer executing conjunctive predicate pushdown, Top-K pushdown into sort nodes, and join-side cardinality selection.
- **Execution Model:** Volcano-style batch-oriented physical operators running homogeneous `RecordBatch` chunks (4,096 rows per batch).
- **Out-of-Core Processing:**
  - *Block Grace Hash Join:* Memory-budgeted partition files with recursive re-hashing or in-memory probe rewinding for skewed partitions.
  - *Partitioned External Aggregation:* Disk-backed hash bucket spill partitions computing partial aggregates (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`).
  - *Hierarchical External Merge Sort:* Memory-bounded in-place sorting flushes sorted runs to disk, merged via bounded fan-in priority queues (preventing OS file descriptor exhaustion).
- **Spill File Container:** Custom binary container format (AXMB v1) with bit-packed NULL bitmaps and non-cryptographic checksums.

#### 2.2 Verified Source Artifacts
- Public interface headers: `include/axiom/` (parser, planner, operators, memory, storage).
- Implementation: `src/` (lexer, parser, binder, physical operators, CSV scanner, AXMB storage).

### 3. Project PRAXIS Source Audit

#### 3.1 Scope & Positioning
- **Dialect & Subsystem Scope:** Restricted, lifetime-safe C++ tree-walking interpreter built in C++20. Does not emit native machine instructions; does not depend on LLVM/Clang at runtime.
- **Frontend Architecture:** Tokenizer and preprocessor supporting `#include` for virtualized headers; recursive-descent AST parser for classes, templates, and functions; semantic type checker with overload resolution.
- **Safety Architecture — Abstract Validated Handle Reference Model:** Pointers are structured descriptor tuples ($\langle \text{targetId}, \text{generation}, \text{targetType}, \text{offset} \rangle$) validated against active allocation tables. Eliminates host virtual memory leakage, traps use-after-free, double-free, and buffer overruns.
- **Deterministic RAII & Memory Management:** Unwinds stack frames with reverse-order destructor invocation; validates dynamic allocations (`new` and `delete`); enforces object allocation quotas (`--max-objects`).
- **Standard Library Subset:** Implements `<vector>`, `<string>`, `<utility>` (`std::pair`, `std::move`, `std::swap`), `<algorithm>` (`std::min`, `std::max`, `std::sort`, `std::reverse`, `std::find`, `std::count`), and range-based for loops.

#### 3.2 Verified Source Artifacts

### 4. Project FORGE Source Audit

#### 4.1 Scope & Positioning
- **Dialect & Subsystem Scope:** Research framework investigating PyTorch CPU operator fusion and native AVX2 SIMD acceleration for deep convolutional network training (ResNet-20 on CIFAR-10 in FP32).
- **Core Technology:** Hand-crafted C++20 AVX2 kernels (`native/src/fused_ops_m2.cpp`) for fused residual addition and ReLU activation; zero-mask backpropagation architecture evaluating $out > 0.0$ in SIMD vector registers to eliminate 2 MB DRAM boolean mask writes.
- **Negative Result & Amdahl's Law Discovery:**
  - *Certified Stock Baseline:* `torch-eager` NHWC (10 threads) = 212.11 ms/step (603.5 samples/s).
  - *Fastest FORGE Configuration:* `forge` NCHW (10 threads) = 249.43 ms/step (513.2 samples/s), achieving 0.8504× stock throughput (513.2 vs 603.5 samples/s, 14.96% lower throughput, 17.59% higher step latency).
  - *Root Cause:* Convolutions (49.43%) and BatchNorm (33.05%) account for 82.48% of runtime; Add+ReLU is only 8.80%, limiting theoretical speedup to 1.0965× by Amdahl's Law. Interleaving custom NCHW kernels destroys oneDNN NHWC memory contiguity.
- **Scientific Integrity:** Full transparency regarding the negative result; zero suppression or manipulation of benchmarks.

#### 4.2 Verified Source Artifacts
- Python extension bindings: `setup_native.py`, `forge/backends/`.
- Native C++ SIMD source: `native/src/fused_ops_m2.cpp`, `native/include/`.
- Verification suite: `tests/numerical/` (29 bitwise parity and gradcheck tests).

### 5. Project VECTRA Source Audit

#### 5.1 Scope & Positioning
- **Dialect & Subsystem Scope:** Clean-room C++20 CPU inference runtime for quantized transformer LLMs (`Qwen2.5-1.5B-Instruct`), engineered with zero dependencies on `llama.cpp`, GGML, or PyTorch.
- **Core Architecture:**
  - *Memory Mapping:* Win32 `MapViewOfFile` maps 1.06 GB GGUF v3 checkpoint directly into virtual memory.
  - *Tokenizer:* Clean-room Byte-Pair Encoding (BPE) engine with ChatML format support.
  - *Zero-Graph Runtime:* Pre-allocated `LayerScratch` workspace eliminates dynamic computational graph allocations, saving 111 MB RAM compared to `llama.cpp`.
  - *Quantized SIMD Kernels:* Fused AVX2 INT8 dot-product micro-kernels contracting `Q8_K_256` activations with `Q4_K` and `Q6_K` block-quantized weights (16 MACs/cycle).
  - *Multi-Projection Fusion:* Fused QKV and Gate-Up projections eliminating 84 thread synchronization barriers per token.
  - *LM-Head Streaming:* Vectorized vocabulary projection streaming at 33.8 GB/s (88% of physical DDR5 peak bandwidth).
