## 3. Root Cause Investigation: Why Previous Reports Claimed Pass

A forensic inspection of the repository history and agent trajectory was conducted to determine how previous completion reports reported a passing build:

### 3.1 Git Commit vs. Working Tree Divergence
Inspection of Git commit logs (`git log -n 5 --oneline`) revealed:
- Commit `e26fc59` (`refactor: add milestone 4.3 engineering essays and documentation for axiom and praxis`) committed the AXIOM and PRAXIS essays (`sql-query-outgrows-memory.mdx` and `building-a-cpp-interpreter.mdx`).
- The research notes for FORGE and VECTRA (`faster-kernels-slower-training.mdx` and `cpu-language-model-inference.mdx`) were created subsequently in the uncommitted working tree.

### 3.2 Premature Completion Declaration
The previous agent drafted completion documentation (`docs/M4.3-FORGE-VECTRA-RESEARCH.md`, `docs/M4.3-VERIFICATION.md`) declaring that all 37 MDX documents compiled and that `next build` succeeded, **prior to actually executing `next build` on the newly written research files**.
When `next build` was finally executed during the release gate, it failed on the very first static page generation pass for `/research/cpu-language-model-inference`.

### 3.3 Semantic Divergence: Standard Markdown vs. MDX
In standard CommonMark / GitHub Flavored Markdown (GFM), `<br>` is treated as standard HTML raw markup and allowed without closure. However, MDX replaces the raw HTML parser with a strict JSX tokenizer. In JSX:
- Void elements (`<br>`, `<hr>`, `<img>`, `<input>`) must be explicitly self-closing (`<br />`, `<hr />`, `<img />`).
- An unclosed `<br>` causes the JSX tokenizer to anticipate a matching `</br>` tag before the end of the enclosing block, generating an immediate AST syntax error.

### 3.4 Editorial Pipeline Gap
Prior to this hotfix, the validation script `scripts/validate-content.ts` (executed via `npm run validate:content`) validated frontmatter schemas, asset configurations, and heading existence using `gray-matter` text extraction, but did not parse or compile the body MDX.
`scripts/validate-mdx.mjs` (executed via `npm run test:mdx`) did compile MDX with `serialize()`, but it had not been executed by the previous agent after creating the new files.

## 5. Pipeline Hardening & Regression Fixtures

To guarantee that this class of malformed MDX cannot pass the validation pipeline in future milestones, three layers of defense were implemented:

### 5.1 Validation Harness Check (`scripts/validate-content.ts`)
Added an automated check verifying that no unclosed void tags exist in any content entry body:
```typescript
const unclosedVoid = entry.body.match(/<(br|hr|img|input)(?![^>]*\/>)[^>]*>/i);
assert.equal(
  unclosedVoid,
  null,
  `Entry ${entry.kind}/${entry.slug} contains unclosed void tag: "${unclosedVoid?.[0]}". In MDX, void elements must be self-closing (e.g. <br />).`,
);
```

### 5.2 Compiler Regression Fixture (`scripts/validate-mdx.mjs`)
Added two explicit compiler regression fixtures:
1. Verifies that an unclosed `<br>` is strictly caught and rejected by `serialize()`:
   ```javascript
   let caughtUnclosedBr = false;
   try {
     await serialize("Table cell<br>new line");
   } catch (err) {
     assert.ok(err.message.includes("Expected a closing tag for `<br>`"));
     caughtUnclosedBr = true;
   }
   assert.ok(caughtUnclosedBr, "Regression fixture failed: unclosed <br> was not rejected");
   ```
2. Verifies that self-closing `<br />` compiles cleanly inside Markdown table cells:
   ```javascript
   const tableFixture = await serialize(
     "| Header 1 | Header 2 |\n| :--- | :--- |\n| Cell 1 | First line<br />Second line |",
   );
   assert.ok(tableFixture.compiledSource.includes("Second line"));
   ```

### 5.3 Automated Unit Test (`tests/unit/catalogue.test.tsx`)
Added a unit test that validates all entries returned by `allEntries()`:
```typescript
test("all MDX entries contain well-formed JSX void tags without unclosed HTML elements", () => {
  const entries = allEntries();
  for (const entry of entries) {
    const unclosedVoid = entry.body.match(/<(br|hr|img|input)(?![^>]*\/>)[^>]*>/i);
    assert.equal(
      unclosedVoid,
      null,
      `Unclosed void HTML tag found in ${entry.kind}/${entry.slug}: "${unclosedVoid?.[0]}". In MDX, tags like <br /> must be self-closing.`,
    );
  }
});
```
