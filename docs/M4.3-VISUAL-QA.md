## 2. Typography & Editorial Rhythm Audit

### 2.1 Font Scaling & Prose Proportions
Long-form technical prose (2,000+ words) requires deliberate typographic calibration to prevent reader fatigue:
- **Body Text:** Rendered using variable serif typography with `font-size: 1.125rem` (18px) on desktop, scaled to `1.0rem` (16px) on mobile viewports.
- **Line Height:** Calibrated at `line-height: 1.75` (31.5px on desktop), allowing eyes to track long paragraphs without jumping lines.
- **Reading Measure:** The `.prose` container enforces a maximum width of `68ch` to `72ch`, ensuring optimal character density per line.
- **Headings Structure:**
  - `h1`: 32px / 2.0rem, bold, with dedicated eyebrow metadata tag.
  - `h2`: 24px / 1.5rem, semi-bold, with generous top margin (`margin-top: 2.5rem`) and auto-generated anchor links.
  - `h3`: 18px / 1.125rem, medium weight, distinct indent.

### 2.2 Table of Contents ("In This Note")
Both essays and research notes feature an sticky/inline Table of Contents (`.table-of-contents`):
- Automatically extracts `h2` and `h3` anchors via `rehypeArticleHeadings`.
- Provides quick-jump anchors with smooth scrolling behavior.
- Inactive links use muted secondary text; hover states subtly elevate color contrast.

## 3. Mathematical Formula Rendering (KaTeX)

The four articles contain over 100 KaTeX mathematical expressions, ranging from inline microarchitectural intensity variables ($I_{\text{decode}} = 3.20\text{ FLOPs/byte}$) to multi-term display equations.

### 3.1 Display Equation Layout & Overflow Protection
- Display equations (`$$...$$`) are rendered inside dedicated block wrappers.
- The `rehypeArticleScrollRegions` plugin automatically wraps display KaTeX containers with:
  ```html
  <div class="katex-display" role="region" tabindex="0" aria-label="Scrollable mathematical equation">
    ...
  </div>
  ```
- **Mobile Overflow Handling:** On narrow mobile screens (390px), wide fraction equations (such as Grace Hash Join I/O or Amdahl's Law derivations) gracefully scroll horizontally without breaking the overall document viewport width.

## 4. Code Blocks & Architecture Diagrams

### 4.1 Code Block Design & Accessible Scrolling
Technical essays present native C++20 algorithms, AVX2 SIMD intrinsics, and SQL physical operators.
- **Syntax Highlighting:** High-contrast monochromatic / syntax-aware tokens tailored for dark and light color themes.
- **Horizontal Scroll Regions:**
  - Each `<pre>` element receives `tabindex="0"`, `role="region"`, and `aria-label="Scrollable code example"`.
  - Enables keyboard-only users to focus and scroll wide code blocks using arrow keys.
- **Line Numbers & Headers:** Clean formatting without visual distraction or excessive chrome.

### 4.2 Interactive Step Diagrams (`<Diagram>`)
Architecture diagrams are presented via the custom `<Diagram>` component:
- Visual step-by-step sequential pipelines (e.g., *Forward Pass* $\to$ *Evaluate y* $\to$ *Save y* $\to$ *Recompute in AVX2 Regs*).
- Clean borders, responsive wrapping on mobile, and semantic figure captions.
- Zero layout shift during client-side hydration.
