#### Roofline Model Derivation & Reconciliation
The mathematical formulation of the Roofline model for quantized transformer autoregressive token generation was verified from first principles:

1. **Arithmetic Work per Token ($W_{FLOP}$):**
   In single-token autoregressive decoding ($B=1$), each weight is read from RAM exactly once per token. The forward pass evaluates two floating-point operations (one multiply, one accumulate) per parameter:
   $$W_{FLOP} \approx 2 \cdot P = 2 \cdot (1.54 \times 10^9) = 3.08 \times 10^9\text{ FLOPs / token}$$

2. **DRAM Traffic per Token ($Q_{DRAM}$):**
   Single-token decoding streams the entire model weight footprint from RAM:
   $$Q_{DRAM} \approx W_{weights} = 1.06 \times 10^9\text{ bytes / token}$$

3. **Operational Intensity ($I$):**
   $$I = \frac{W_{FLOP}}{Q_{DRAM}} = \frac{3.08 \times 10^9\text{ FLOPs}}{1.06 \times 10^9\text{ bytes}} \approx 2.9056\text{ FLOP / byte} \approx 2.91\text{ FLOP / byte}$$

4. **Hardware Performance Bounds (Intel Core i7-12650H with DDR5):**
   - **Theoretical Peak Compute ($P_{peak}$):** Sustained thermal throttling ceiling of AVX2/FMA3 vector execution $\approx 450\text{ GFLOP/s}$.
   - **Measured STREAM Triad Memory Bandwidth ($B_{STREAM}$):** Host STREAM Triad memory throughput measured at $36.8\text{ GB/s}$ (`E:\VECTRA\audit\m4\HARDWARE_PROFILING.md`). Single-channel DDR5-4800 analytical peak is $38.4\text{ GB/s}$.
   - **Machine Balance ($B_{mach}$):**
     $$B_{mach} = \frac{P_{peak}}{B_{STREAM}} = \frac{450 \times 10^9\text{ FLOP/s}}{36.8 \times 10^9\text{ bytes/s}} \approx 12.23\text{ FLOP / byte} \quad \left(\text{or } \frac{450}{38.4} \approx 11.72\text{ FLOP/byte}\right)$$

5. **Roofline Regime & Decode Ceilings:**
   Since $I = 2.91\text{ FLOP/byte} \ll B_{mach} \approx 11.72–12.23\text{ FLOP/byte}$, execution is strictly situated in the **Memory-Bandwidth Bound** regime.
   - **Empirical STREAM Triad Ceiling:**
     $$\text{Ceiling}_{\text{STREAM}} = \frac{36.8 \times 10^9\text{ bytes/s}}{1.0656 \times 10^9\text{ bytes/token}} \approx 34.5\text{ tokens/second}$$
   - **Theoretical Channel Ceiling:**
     $$\text{Ceiling}_{\text{channel-ideal}} = \frac{38.4 \times 10^9\text{ bytes/s}}{1.06 \times 10^9\text{ bytes/token}} \approx 36.2\text{ tokens/second}$$

6. **Measured Release Benchmarks on Intel Core i7-12650H:**

   - **Batched Prefill Throughput (Prompt P3, 16 prompt tokens):** Sustained median **$24.13\text{ tok/s}$** ($663.1\text{ ms}$), peak warm **$25.92\text{ tok/s}$** ($617.29\text{ ms}$).

### 2.3 FORGE: Throughput Deficit vs. Execution-Time Ratio Precision

#### Discrepancy Identified
Preliminary documentation suffered from two critical inaccuracies:
1. *Metric Units & Workload Conflation:* Draft notes erroneously labeled the training throughput in "tokens/sec" and conflated the benchmark with a GPU model. The actual canonical project in `E:\FORGE` is a **CPU training acceleration framework for ResNet-20 on CIFAR-10 in FP32**, measured strictly in **samples/sec**.
2. *Throughput vs. Latency Conflation:* Preliminary text characterized the $0.8504\times$ ratio simply as "a 17.59% deficit", which conflated the throughput ratio ($513.2 / 603.5 = 0.8504$) with the step latency inflation ($249.43 / 212.11 = 1.1759$).

#### Source Artifact Investigation
- **Authoritative Repository:** `Zylus08/FORGE` (`E:\FORGE`)
- **Benchmark Manifest:** `E:\FORGE\audit\rc1\BASELINE_CERTIFICATION.md` and `E:\FORGE\README.md`
- **Experimental Setup:** ResNet-20 on CIFAR-10 (269,722 parameters), batch size 128, FP32 precision on 12th Gen Intel Core i7-12650H processor (10 physical cores: 6 P-cores + 4 E-cores, 16 threads, AVX2 SIMD, Windows 11 x64, 16 GB DDR5), PyTorch 2.1.2 + custom native C++20 autograd extension.
- **Measured Metrics:**
  - **Stock Baseline Competitor (`torch-eager` Channels-Last `NHWC`, 10 physical threads):**
    - Step Latency ($T_{stock}$): $212.11\text{ ms / step}$ (95% CI [207.50, 216.72] ms)
    - Training Throughput ($\Theta_{stock}$): $603.5\text{ samples / sec}$
  - **Fastest Valid FORGE Configuration (`forge` Contiguous `NCHW`, 10 physical threads):**
    - Step Latency ($T_{forge}$): $249.43\text{ ms / step}$ (95% CI [236.97, 261.89] ms)
    - Training Throughput ($\Theta_{forge}$): $513.2\text{ samples / sec}$

#### Mathematical Reconciliation
1. **Throughput Ratio:**
   $$\rho_{\Theta} = \frac{\Theta_{forge}}{\Theta_{stock}} = \frac{513.2\text{ samples/sec}}{603.5\text{ samples/sec}} = 0.8503728... \approx 0.8504 = 85.04\%$$
   The training throughput deficit relative to stock is:
   $$\Delta \Theta = 1 - \rho_{\Theta} = 1 - 0.8504 = 0.1496 = 14.96\% \quad \text{(i.e. 14.96% lower throughput)}$$

2. **Step Latency Inflation Ratio:**
   $$\rho_{T} = \frac{T_{forge}}{T_{stock}} = \frac{249.43\text{ ms}}{212.11\text{ ms}} = 1.175946... \approx 1.1759 = 117.59\%$$
   The step latency increased by:
   $$\Delta T = \rho_{T} - 1 = 1.1759 - 1 = 0.1759 = 17.59\% \quad \text{(i.e. 17.59% higher step latency)}$$
   Stock PyTorch completed each training step $17.59\%$ faster than FORGE.

3. **Amdahl's Law Forensic Breakdown:**
   - 2D Convolutions (`torch.nn.Conv2d`): $49.43\%$ of step time ($104.84\text{ ms}$).
   - Batch Normalization (`torch.nn.BatchNorm2d`): $33.05\%$ of step time ($70.10\text{ ms}$).
   - Total Non-Accelerated Execution ($1 - f$): **$82.48\%$** ($174.95\text{ ms}$).
   - Residual Add + ReLU Operations ($f$): **$8.80\%$** ($18.67\text{ ms}$).
   - Theoretical Maximum Speedup:
     $$S_{\text{max}} = \frac{1}{(1 - f) + \frac{f}{\infty}} = \frac{1}{1 - 0.0880} = \frac{1}{0.9120} \approx 1.0965\times$$
   - Root Cause of the 0.8504× Slowdown:
     - NHWC-to-NCHW format conversion copying introduced $23.19\text{ ms}$ of memory copying overhead.
     - Zero-mask activation re-reading during backpropagation evicted convolution weights from CPU L2 cache.
   - Bitwise Parity: **29/29 regression tests passed** with exact bitwise parity ($L_\infty = 0.0$ across 3,674,112 elements).

#### Corrective Actions Taken
- Updated `src/content/projects/forge.mdx`, `src/content/research/faster-kernels-slower-training.mdx`, `src/components/first-principles-collection.tsx`, and all documentation files:
  - Enforced metric: **513.2 vs 603.5 samples/sec**.
  - Enforced ratio: **0.8504× stock throughput**.
  - Enforced dual metrics: **14.96% lower throughput** and **17.59% higher step latency**.
  - Strictly banned "tokens/sec" for this training benchmark.
