## Browser failures and resolution

The first complete 128-case run had three failures: one desktop Kamish layout/accessibility timeout and the new root-canonical expectation on desktop and mobile. The Kamish trace recorded Chrome `ERR_INSUFFICIENT_RESOURCES` and a stalled bounding-box call, before the axe assertion. A fresh focused run passed the same unmodified Kamish case on both devices. The root canonical was valid but serialized without the trailing slash assumed by the new test; the exact expected URL was corrected. The complete metadata test then passed on both devices, including OG PNG dimensions, historical URL HTTP 200, naming, sitemap, robots and pending-research noindex.

Focused command: `node node_modules/playwright/cli.js test --grep "recruiter metadata|catalogue accessibility and responsive layout: projects/hydra-stream"`, bounded to 300 seconds. Results: four passed, zero failures. Log: `.tmp/m412-browser-rerun.log`. This is not represented as a single uninterrupted green full-suite run.

The final diff leaves contact implementation/configuration, four PDFs, all MDX bodies, Journey data and profile configuration unchanged. Historical milestone screenshots were restored after tests; only new M4.1.2 captures are included. Generated `next-env.d.ts` was restored to its baseline content. No unresolved implementation blocker was found for this local milestone; deployment remains unperformed.
